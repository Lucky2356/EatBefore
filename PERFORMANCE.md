# Производительность

Скелет с бюджетами. Профилирование основных сценариев — по мере роста функциональности.

## Бюджеты (целевые, устройство среднего уровня)

| Метрика | Бюджет |
|---------|--------|
| Холодный запуск до интерактивности | < 1.5 с |
| Открытие экрана запасов | < 300 мс |
| Поиск (после debounce) | < 150 мс на локальной базе |
| Прокрутка списков | 60 fps, без пропусков кадров |
| Пиковое потребление памяти (обычный сценарий) | < 150 МБ |

## Заложенные меры (Foundation)

- Холодный запуск **без сетевых запросов** (local-first).
- Ленивые списки (`LazyColumn`) со стабильными ключами (`batchId`).
- Индексы Room на часто используемых колонках (barcode, product_id,
  storage_location_id, expiration_date, status).
- Debounce поиска (250 мс), фильтрация/сортировка вне главного потока (Flow + `stateIn`).
- `WhileSubscribed(5s)` — подписки не живут дольше нужного.
- Мапперы и агрегаты (`InventoryItem`) через один запрос с `@Relation` (без N+1).
- Корректная отмена корутин (viewModelScope), отсутствие постоянного опроса.

## Планируется

- Пагинация больших историй.
- Сжатие изображений и thumbnail (со сканером/OCR).
- Кеширование ответов внешнего каталога.
- Пакетирование уведомлений (без ежедневного спама), разумные WorkManager-задачи.
- Baseline Profiles, трассировка Macrobenchmark на ключевых сценариях.
