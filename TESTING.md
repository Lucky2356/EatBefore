# Тестирование

## Как запускать

```bash
./gradlew :app:testDebugUnitTest            # unit + интеграционные (JVM/Robolectric)
./gradlew :app:connectedDebugAndroidTest    # инструментальные (нужно устройство/эмулятор)
```

## Что покрыто — 55 unit + 1 инструментальный тест, 0 падений

### Unit (чистый JVM)
- `DetermineExpiryStatusUseCaseTest` — статусы срока (нет даты/просрочен/сегодня/скоро/свежий).
- `CalculateExpirationAfterOpeningUseCaseTest` — срок после открытия, ограничение печатным сроком.
- `InventoryUseCasesTest` — ручное добавление (создание/дедуп карточки), изменение
  количества (частичное/до нуля → CONSUMED + soft-delete), открытие, выброс, перемещение,
  восстановление, отмена последнего действия; проверка соответствия события состоянию.
- `MergeSameProductUseCaseTest` — приоритет штрихкода, регистронезависимый матч по имени+бренду.
- `LookupProductByBarcodeUseCaseTest` — кеш-хит без сети, кеширование сетевого результата,
  обработка ошибки/«не найдено».
- `ExpiryDateParserTest` (11 тестов) — форматы дат, month-year → конец месяца, различие
  «годен до»/«дата изготовления», отсев неправдоподобных/невалидных дат.
- `NotificationLogicTest` (5 тестов) — подсчёт просрочено/сегодня/скоро, пустой план,
  тихие часы (в т.ч. с переходом через полночь).
- `ShoppingListUseCasesTest` (7 тестов) — добавление свободного товара, слияние
  повторного добавления продукта, событие истории при добавлении из списанной партии,
  toggle «куплено», удаление, возврат в запасы (связанный продукт и свободный текст).

### Инструментальные (на устройстве/эмуляторе)
- `ExpiryCheckWorkerTest` — реальный `ExpiryCheckWorker` через `TestListenableWorkerBuilder`
  + `HiltWorkerFactory`: сеет истекающий сегодня продукт, запускает воркер, проверяет
  успех и публикацию системного уведомления (`NotificationManager.activeNotifications`).

### Интеграционные (Robolectric, Room in-memory)
- `EatBeforeDatabaseTest` — seed мест хранения, insert/query, исключение soft-deleted из present.
- `InventoryFlowIntegrationTest` — реальный стек (Room + репозитории + use cases):
  ручное добавление → present-запас + запись истории; изменение количества → undo.

## Подход

- Внешние сервисы (каталог, OCR) — fake/noop-реализации.
- Время абстрагировано через `AppClock` (в тестах — `FakeAppClock`).
- Репозитории-фейки (`FakeRepositories`) для изоляции use cases от Room.
- Robolectric зафиксирован на API 34 (`robolectric.properties`), т.к. sandbox для API 36
  ещё не поставляется; тестируемые пути (java.time/Room) идентичны.

## Планируется (следующие итерации)

- UI-тесты (Compose) для 8 ключевых сценариев ТЗ: ручное/сканированное добавление,
  изменение количества, «закончилось», восстановление из истории, добавление в покупки,
  переключение темы, работа без интернета.
- Тесты миграций при повышении версии схемы.
- Тесты WorkManager (уведомления) и резервного копирования.
