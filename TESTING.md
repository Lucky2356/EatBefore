# Тестирование

## Как запускать

```bash
./gradlew :app:testDebugUnitTest            # unit + интеграционные (JVM/Robolectric)
./gradlew :app:connectedDebugAndroidTest    # инструментальные (нужно устройство/эмулятор)
```

Инструментальные тесты запускаются и в CI — job «Instrumented tests (emulator)» на
push в `main` (не на каждый PR: прогон занимает около двадцати минут). Это возвращает
`MigrationTest` в автоматику: он единственная автоматическая защита данных при
обновлении, и раньше выполнялся только тогда, когда о нём вспоминали.

## Что покрыто — 195 unit + 12 инструментальных тестов, 0 падений

### Доменная логика (чистый JVM)
- `DetermineExpiryStatusUseCaseTest` (5) — статусы срока (нет даты/просрочен/сегодня/скоро/свежий).
- `CalculateExpirationAfterOpeningUseCaseTest` (4) — срок после открытия, ограничение печатным сроком.
- `OpeningShelfLifeTest` (7) — сроки после вскрытия по категориям.
- `InventoryUseCasesTest` (11) — ручное добавление (создание/дедуп карточки), изменение
  количества (частичное/до нуля → CONSUMED + soft-delete), открытие, выброс, перемещение,
  восстановление, отмена последнего действия; соответствие события состоянию.
- `UpdateItemDetailsUseCaseTest` (6) — правка названия/бренда/категории/срока/заметки.
- `MergeSameProductUseCaseTest` (3) — приоритет штрихкода, регистронезависимый матч по имени+бренду.
- `LookupProductByBarcodeUseCaseTest` (4) — кеш-хит без сети, кеширование сетевого результата,
  обработка ошибки/«не найдено».
- `ChainedCatalogProviderTest` (7) — порядок обхода каталогов, переход к следующему при отказе.
- `ExpiryDateParserTest` (11) — форматы дат, month-year → конец месяца, различие
  «годен до»/«дата изготовления», отсев неправдоподобных/невалидных дат.
- `Gs1ParserTest` (11) — коды «Честного знака»: GTIN из AI 01, срок из AI 17/15
  (DD=00 → конец месяца), партия/серийник, GS-разделители, префиксы `]d2`, отличение от
  обычного EAN/URL, невалидные даты.
- `NotificationLogicTest` (5) — подсчёт просрочено/сегодня/скоро, пустой план,
  тихие часы (в т.ч. с переходом через полночь).
- `ShoppingListUseCasesTest` (7) — добавление свободного товара, слияние повторного
  добавления продукта, событие истории при списании, toggle «куплено», удаление,
  возврат в запасы.
- `BuildAnalyticsUseCaseTest` (7) — счётчики по периодам, категории отходов, топ покупок,
  «использовано вовремя» %.
- `InputValidatorTest` (6) — нормализация названий, штрихкодов, границы длины.

### ViewModel (JVM, `MainDispatcherRule` + Turbine/mockk)
Логика экранов раньше проверялась только через настоящий интерфейс — медленно и без
объяснения причины падения.
- `ProductViewModelTest` (13) — загрузка партии со статусом срока, undo после каждого
  разрушительного действия, предложение списка покупок только когда товар кончился,
  закрытие экрана только после действия (а не на первом кадре, когда партия ещё не
  подгрузилась).
- `ScannerViewModelTest` (16) — разбор GS1-маркировки (поиск по GTIN, срок из кода),
  дедупликация непрерывного потока детекций ML Kit в пакетном режиме, парковка
  неизвестных кодов до конца прохода, поведение без места хранения по умолчанию.
- `AddManualViewModelTest` (17) — предвыбор места по умолчанию, валидация, фильтрация
  количества, и главное — товар не уходит в общий каталог без явного подтверждения:
  ни без штрихкода, ни без привязанного аккаунта, ни при отказе.

### Данные и синхронизация
- `SyncEngineTest` (12) — правила слияния: сходимость двух баз, повторный обмен ничего
  не меняет, устаревшее устройство не «воскрешает» съеденное.
- `SyncManagerTest` (12, Robolectric) — вторая половина обмена: работа с файлами общей
  папки. Публикуется ровно один свой журнал; повторный обмен перезаписывает его, а не
  добавляет второй; дубликат своего журнала подчищается, а чужой файл не трогается
  никогда; посторонние файлы в папке остаются на месте; битый журнал соседа
  пропускается, но свой всё равно публикуется. Вместо SAF — обычный временный каталог
  (см. `SyncFolderResolver`).
- `UuidIdentityTest` (7) — идентичность записи переживает обычную правку. Регрессия,
  попавшая в v1.4.0: доменный слой терял `uuid`, и списание на втором телефоне
  превращалось в новую партию.
- `BackupManagerTest` (11, Robolectric+Room) — roundtrip экспорт→очистка→импорт,
  повреждённый JSON, подделка counts и чужая версия схемы отклоняются без потери данных.
- `DiagnosticsLogTest` (8) — формат записи, обрезка целыми записями по количеству и
  размеру, устойчивость записи при недоступном файле (обработчик сбоя не должен падать сам).
- `EatBeforeDatabaseTest` (3) — seed мест хранения, insert/query, исключение soft-deleted.
- `InventoryFlowIntegrationTest` (2) — реальный стек (Room + репозитории + use cases).

### Инструментальные (на устройстве/эмуляторе)
- `MigrationTest` (3) — миграции Room на настоящей SQLite с данными. Единственная
  автоматическая проверка того, что обновление не потеряет запасы пользователя.
- `AppFlowTest` (8) — сквозные сценарии в настоящем приложении: ручное добавление,
  изменение количества, список покупок, история, смена темы, подтверждение импорта.
- `ExpiryCheckWorkerTest` (1) — реальный воркер через `TestListenableWorkerBuilder`
  + `HiltWorkerFactory`, проверка публикации системного уведомления.

## Подход

- Внешние сервисы (каталог, OCR) — fake/noop-реализации.
- Время абстрагировано через `AppClock` (в тестах — `FakeAppClock`), поэтому «скоро
  истекает» и дедупликация сканера проверяются без ожиданий.
- Репозитории-фейки (`FakeRepositories`) для изоляции use cases от Room.
- Robolectric зафиксирован на API 34 (`robolectric.properties`), т.к. sandbox для API 36
  ещё не поставляется; тестируемые пути (java.time/Room) идентичны.
- Таймаут ожидания в UI-тестах — 30 с. Он расходуется только когда тест и так падает,
  а эмулятор в CI в разы медленнее рабочей машины.

## Чего не хватает

- Поведение настоящего облачного клиента: наполовину записанный файл, конфликтные копии,
  задержка синхронизации диска. Временный каталог этого не воспроизводит — проверять
  только на двух реальных телефонах.
- Остальные десять ViewModel (`HomeViewModel`, `InventoryViewModel`, `SettingsViewModel`,
  `ShoppingViewModel`, `AnalyticsViewModel`, `HistoryViewModel` и другие).
