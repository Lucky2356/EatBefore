# Roadmap

Приоритеты соответствуют ТЗ. Foundation закрывает инфраструктуру и часть P0; остальное
идёт последующими итерациями.

## Foundation (готово)

Gradle/DI/тема, Room + миграции + seed, репозитории и use cases, навигация, экраны
onboarding/home/inventory/add/product/history, тесты, документация.

## P0 — обязательно (после Foundation)

- [x] **Сканер**: CameraX preview, ML Kit barcode (EAN-13/8, UPC, QR, DataMatrix),
      подсветка области, фонарик, антидубль, ручной ввод, обработка отказа камеры.
- [x] **Внешний каталог**: реализация `ProductCatalogProvider` (Open Food Facts) —
      таймауты, HTTPS, кеширование, корректная обработка «не найдено», правка данных
      пользователем, без блокировки ручного добавления при ошибке, повторы с
      нарастающей паузой на 429/5xx, изображение товара в подтверждении сканирования.
      Отдельный клиентский rate-limit снят как переусложнение: чтобы упереться в лимит
      «15 запросов в минуту», одному домохозяйству надо сканировать по товару каждые
      четыре секунды.
- [x] **OCR срока годности**: `ExpiryDateOcrProvider` на ML Kit text recognition —
      несколько форматов дат (dd.MM.yyyy, dd.MM.yy, MM.yyyy, ISO, «dd MON yyyy»),
      различие «годен до»/«дата изготовления» по близости метки, показ исходного текста,
      подтверждение пользователем, обработка неуверенного/пустого результата, удаление
      снимка после распознавания, фотография из галереи как источник.
      Cyrillic-модель снята как невыполнимая: в ML Kit её нет — v2 предлагает латиницу,
      китайский, деванагари, японский и корейский. Практического ущерба нет, сроки
      годности это цифры и разделители, а русские месяцы разбирает `ExpiryDateParser`.
- [x] **Уведомления**: WorkManager (ежедневная проверка; просрочено/сегодня/скоро),
      пакетирование («сегодня стоит проверить N продуктов»), тихие часы, настройки
      (вкл/выкл, время, дни, интервал), запрос POST_NOTIFICATIONS в нужный момент,
      отключение напоминаний для конкретного продукта (свойство карточки, уезжает на
      второй телефон). Дробление на отдельные каналы снято: одно пакетное уведомление —
      осознанное решение против спама, записанное в комментарии `ExpiryNotifier`.
- [x] **Список покупок**: UI, группировка по категориям, отметка выполнения, быстрый
      возврат в запасы («В запасы» одним нажатием), ручное добавление, предложение при
      списании, слияние повторного добавления одного товара, событие в истории,
      приоритеты, подсказка регулярных покупок из истории добавлений.
- [x] **Аналитика**: добавлено/использовано/выброшено/просрочено, «использовано вовремя»
      %, категории выброса, регулярные покупки; периоды 7/30/365/всё время. Без
      псевдоточной финансовой аналитики.
- [x] **Резервное копирование**: JSON-экспорт/импорт с версией схемы и проверкой
      целостности (counts), подтверждение перед заменой, атомарный импорт (транзакция),
      лимит размера файла, обработка повреждённого файла, режим слияния.
- [x] **Режимы количества**: простой (кнопки в карточке) и подробный — точный ввод
      количества по тапу на число в карточке продукта.
- [x] **«Честный знак» / GS1**: парсер DataMatrix/QR (AI 01/17/15/10/21, GS-разделители,
      префиксы символогий) — GTIN для поиска товара, срок годности из кода
      автоматически подставляется в партию/форму.
- [x] **Качество**: lint без ошибок, detekt и ktlint в CI, Baseline Profile,
      юнит- и инструментальные тесты (последние — на push в `main`), ручная проверка
      тёмной темы, офлайна и разрешений.

## P1 — после стабильного P0

- **Совместный доступ (семья, 2+ устройства)** — спроектирован, см.
  [ADR-0004](docs/adr/0004-household-sharing.md): синхронизация журналом событий
  через общий файл на диске пользователя (v1.1), затем по локальной сети (v1.2).
  Подготовка: uuid для products/batches/events, deviceId в событиях (миграция Room).
- Аналитика пищевых отходов (расширенная), домашние блюда и заготовки, шаблоны частых
  покупок, повтор покупки, расширенные единицы измерения, Android-виджет, улучшенный
  DataMatrix, персональные настройки уведомлений.

## P2 — только архитектурный задел (интерфейсы + ADR, без фиктивных экранов)

- Учётная запись и семейный доступ, серверная синхронизация, несколько устройств,
  совместный список покупок, рецепты из имеющихся продуктов, сканирование чеков,
  учёт расходов, интеллектуальные рекомендации.

P2 не должен усложнять P0: облачная синхронизация подключается за интерфейсами
репозиториев и не встраивается в локальную бизнес-логику.
