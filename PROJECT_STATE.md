# Состояние проекта

Обновлено: 2026-07-15. Milestones **Foundation**, **Сканер**, **OCR срока**,
**Уведомления**, **Список покупок**, **Финал P0 (ЧЗ/GS1, аналитика, бэкап)** — завершены.
**Весь обязательный объём P0 реализован и проверен**; из «Качества» остаются полные
Compose-UI-тесты 8 сценариев и detekt/ktlint (см. TODO).

## Финал P0 (что реализовано и проверено)

- **«Честный знак»/GS1**: `Gs1Parser` (11 тестов) — GTIN из AI 01 (нормализация 14→13),
  срок из AI 17/15 (включая DD=00 → конец месяца), партия/серийник, GS-разделители,
  `]d2`-префиксы. Сканер: GS1-код → поиск по GTIN → срок из кода в партию/форму.
  Проверено на эмуляторе: реальный русский товар `4601662000016` (Parmalat «Молоко
  ультрапастеризованное 3,5 %») найден в OFF; ЧЗ-код с тем же GTIN найден офлайн из
  кеша со сроком 2027-09-01; неизвестный русский GTIN → ручное добавление с
  предзаполненными штрихкодом и сроком 2026-12-31 — всё подтверждено содержимым БД.
- **Аналитика**: `BuildAnalyticsUseCase` (5 тестов) + экран (плитки, «использовано
  вовремя» %, категории отходов, регулярные покупки, периоды). Проверено на устройстве.
- **Бэкап**: `BackupManager` (4 теста: roundtrip, повреждённый JSON, подделка counts,
  чужая версия — данные не затрагиваются) + экспорт/импорт в настройках через SAF с
  подтверждением замены и лимитом 20 МБ.
- **Исправления**: краш-баги NewApi (ofInstant→atZone, minSdk 26!), залипание карточки
  «Товар найден», перенос «Сканироват ь», дубль заголовка «Количество». Lint: 0 ошибок.
- **Дизайн**: выделенный сканер в нижней навигации, плитки статистики на главной,
  карточки запасов с иконками мест, аккуратные скругления; светлая и тёмная темы
  проверены скриншотами.

## Milestone «Список покупок» (что реализовано и проверено)

- `ShoppingListRepository` (+ impl) и 4 use case: `AddToShoppingListUseCase`
  (слияние одинакового товара по количеству, событие `ADDED_TO_SHOPPING_LIST` при
  добавлении из списанной партии), `ToggleShoppingItemUseCase`,
  `DeleteShoppingItemUseCase`, `MoveShoppingItemToInventoryUseCase` («купил → в запасы»).
- `HistoryRepository.record(...)` — запись самостоятельных событий (не мутаций партии).
- Экран покупок: группировка по категориям, чекбокс «куплено» (зачёркивание), количество,
  ручное добавление (FAB + диалог с валидацией), «В запасы» и удаление; empty state.
- Карточка продукта: быстрое действие «В покупки» + диалог-предложение после
  «закончилось»/«выбросить».
- 7 unit-тестов (слияние, событие истории, toggle, удаление, возврат в запасы для
  связанного продукта и для свободного текста).
- Проверено на эмуляторе: добавление → группировка → «В запасы» (появился в Запасах,
  Холодильник) → «Закончилось» → предложение → товар снова в списке покупок.

## Milestone «Уведомления» (что реализовано и проверено)

- `BuildExpiryNotificationUseCase` (чистый) + `isWithinQuietHours` — 5 unit-тестов
  (подсчёт просрочено/сегодня/скоро, тихие часы с переходом через полночь).
- `ExpiryCheckWorker` (@HiltWorker, CoroutineWorker): ежедневная проверка, учёт вкл/выкл
  и тихих часов; `NotificationScheduler` — уникальная периодическая задача (24ч) на
  выбранное время, переустановка при смене настроек; `ExpiryNotifier` — канал + одно
  **пакетное** уведомление (замена, не стек → без спама), проверка POST_NOTIFICATIONS.
- Экран настроек: вкл/выкл, время (TimePicker), «за сколько дней» (слайдер 1..14),
  тихие часы; запрос POST_NOTIFICATIONS в момент включения, реактивное предупреждение.
- Планирование связано в `EatBeforeApplication` (канал + автоперепланирование при смене
  настроек).
- Проверено: инструментальный тест `ExpiryCheckWorkerTest` на эмуляторе (API 35) —
  реальный воркер публикует системное уведомление; экран настроек и системный запрос
  разрешения проверены вручную (скриншоты).

## Milestone «OCR срока годности» (что реализовано и проверено)

- `ExpiryDateParser` (чистый, 11 unit-тестов): форматы dd.MM.yyyy / dd.MM.yy / MM.yyyy /
  ISO / «dd MON yyyy» (EN+RU месяцы); month-year → конец месяца; различие «годен до» и
  «дата изготовления» по близости метки; ранжирование по уверенности; отсев неправдоподобных дат.
- `MlKitExpiryDateOcrProvider`: ML Kit text recognition on-device, лимит размера изображения,
  устойчивость к ошибкам (пустой результат вместо падения).
- Экран OCR: CameraX ImageCapture, показ исходного текста и кандидатов, подтверждение
  пользователем, экран «Дата не распознана», снимок удаляется после обработки (приватность).
- Интеграция: кнопка «Распознать по фото» в форме добавления, дата возвращается в форму.
- Проверено на эмуляторе (API 35): съёмка → распознавание → корректный экран «не распознано»
  (виртуальная сцена без даты) → возврат в форму; временный файл снимка удалён.

## Milestone «Сканер» (что реализовано и проверено)

- CameraX preview + ML Kit barcode (on-device): EAN-13/8, UPC-A/E, QR, DataMatrix,
  Code-128; подсветка области, фонарик, антидубль (3 с), ручной ввод кода, устойчивая
  обработка отсутствия/отказа камеры (без падения).
- Реальный `ProductCatalogProvider` на Open Food Facts (OkHttp, таймауты 5/5/8 с,
  User-Agent, HTTPS); ответы валидируются как недоверенные; ошибка/не найдено не
  блокируют ручной ввод. Найденный товар кешируется локально (SCAN_CACHE).
- Поток: найден → «Добавить упаковку» / «Подробнее»; не найден/ошибка → добавить вручную
  (форма предзаполняется штрихкодом). Запрос разрешения камеры — в момент использования.
- Проверено на эмуляторе (API 35): ввод кода 3017620422003 → найден «Nutella» из каталога
  → добавлена упаковка (Холодильник, «Без срока») → на главной «Всего продуктов: 2».
- Тесты: `LookupProductByBarcodeUseCaseTest` (кеш-хит без сети, кеширование сетевого
  результата, ошибка/не найдено). Всего 32 unit/интеграционных теста, 0 падений.

## Что реализовано

- Тулчейн настроен (JDK 21 из Android Studio, Android SDK Platform 36, build-tools).
- Gradle-проект: Version Catalog, Compose, Hilt, Room, KSP, wrapper 8.11.1, AGP 8.10.1.
- Модель данных Room: products, inventory_batches, inventory_events, storage_locations,
  shopping_list_items; converters, индексы, seed мест хранения, экспорт схемы v1.
- Домен: модели, enum-ы, интерфейсы репозиториев и провайдеров, 11 use cases.
- Data: реализации 4 репозиториев, мапперы, атомарные мутации с записью истории,
  fake-провайдеры каталога и OCR.
- Дизайн-система: тема M3 (светлая/тёмная + dynamic color), статус-бейджи (иконка+текст),
  empty/error/loading, quick-action кнопки, форматтеры.
- Экраны: онбординг (3 стр.), главная, запасы (поиск/фильтр/сортировка), ручное
  добавление, карточка продукта (быстрые действия + история + undo), история
  (фильтры, восстановление, отмена последнего). Нижняя навигация + NavHost.
- Заглушки-«coming soon»: сканер (ведёт к ручному добавлению), покупки, ещё.

## Известные проблемы / ограничения

- Runtime-проверка на устройстве не выполнена: на машине нет AVD/устройства. Стек
  проверен интеграционными тестами на JVM (Robolectric); сборка APK не блокируется.
- `product` карточка показывает историю по продукту; постраничная загрузка больших
  историй ещё не добавлена (сейчас списки небольшие).
- Экспорт/импорт и реальные внешние сервисы отсутствуют (заглушки/интерфейсы).
