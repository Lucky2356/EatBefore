# Состояние проекта

Обновлено: 2026-09-06.

**Последний релиз — [1.11.0](https://github.com/Lucky2356/EatBefore/releases/tag/v1.11.0)**
(versionCode 13, опубликован 21.08.2026, подписан рабочим ключом).

Весь обязательный объём **P0 реализован, проверен на устройстве и выпущен**. Milestones
**Foundation**, **Сканер**, **OCR срока**, **Уведомления**, **Список покупок**,
**Финал P0 (ЧЗ/GS1, аналитика, бэкап)** — завершены. Из «Качества» тоже не осталось
ничего: Compose-UI-тесты, detekt и ktlint написаны и стоят в CI.

Сейчас в репозитории **395 юнит-тестов и 21 инструментальный**, 238 файлов Kotlin,
6 ADR. Сборка, тесты и публикация подписанного релиза идут целиком в GitHub Actions —
на компьютере не нужно ничего, кроме браузера ([docs/CLOUD.md](docs/CLOUD.md)).

## Финал P0 (что реализовано и проверено)

- **«Честный знак»/GS1**: `Gs1Parser` (11 тестов) — GTIN из AI 01 (нормализация 14→13),
  срок из AI 17/15 (включая DD=00 → конец месяца), партия/серийник, GS-разделители,
  `]d2`-префиксы. Сканер: GS1-код → поиск по GTIN → срок из кода в партию/форму.
  Проверено на эмуляторе: реальный русский товар `4601662000016` (Parmalat «Молоко
  ультрапастеризованное 3,5 %») найден в OFF; ЧЗ-код с тем же GTIN найден офлайн из
  кеша со сроком 2027-09-01; неизвестный русский GTIN → ручное добавление с
  предзаполненными штрихкодом и сроком 2026-12-31 — всё подтверждено содержимым БД.
- **Аналитика**: `BuildAnalyticsUseCase` (5 тестов) + экран (плитки, «использовано
  вовремя» %, категории отходов, регулярные покупки, периоды). Проверено на устройстве.
- **Бэкап**: `BackupManager` (4 теста: roundtrip, повреждённый JSON, подделка counts,
  чужая версия — данные не затрагиваются) + экспорт/импорт в настройках через SAF с
  подтверждением замены и лимитом 20 МБ.
- **Исправления**: краш-баги NewApi (ofInstant→atZone, minSdk 26!), залипание карточки
  «Товар найден», перенос «Сканироват ь», дубль заголовка «Количество». Lint: 0 ошибок.
- **Дизайн**: выделенный сканер в нижней навигации, плитки статистики на главной,
  карточки запасов с иконками мест, аккуратные скругления; светлая и тёмная темы

## Milestone «Список покупок» (что реализовано и проверено)

- Карточка продукта: быстрое действие «В покупки» + диалог-предложение после
  «закончилось»/«выбросить».
- 7 unit-тестов (слияние, событие истории, toggle, удаление, возврат в запасы для
  связанного продукта и для свободного текста).

## Milestone «Уведомления» (что реализовано и проверено)

- `BuildExpiryNotificationUseCase` (чистый) + `isWithinQuietHours` — 5 unit-тестов

  тихие часы; запрос POST_NOTIFICATIONS в момент включения, реактивное предупреждение.
- Планирование связано в `EatBeforeApplication` (канал + автоперепланирование при смене
  настроек).
- Проверено: инструментальный тест `ExpiryCheckWorkerTest` на эмуляторе (API 35) —
  реальный воркер публикует системное уведомление; экран настроек и системный запрос

## Milestone «OCR срока годности» (что реализовано и проверено)

- `ExpiryDateParser` (чистый, 11 unit-тестов): форматы dd.MM.yyyy / dd.MM.yy / MM.yyyy /
  ISO / «dd MON yyyy» (EN+RU месяцы); month-year → конец месяца; различие «годен до» и
  «дата изготовления» по близости метки; ранжирование по уверенности; отсев неправдоподобных дат.
- `MlKitExpiryDateOcrProvider`: ML Kit text recognition on-device, лимит размера изображения,
  устойчивость к ошибкам (пустой результат вместо падения).
- Экран OCR: CameraX ImageCapture, показ исходного текста и кандидатов, подтверждение
  пользователем, экран «Дата не распознана», снимок удаляется после обработки (приватность).
- Интеграция: кнопка «Распознать по фото» в форме добавления, дата возвращается в форму.
- Проверено на эмуляторе (API 35): съёмка → распознавание → корректный экран «не распознано»
  (виртуальная сцена без даты) → возврат в форму; временный файл снимка удалён.

## Известные ограничения

- **Ключ подписи существует в двух местах** — у владельца и в секретах репозитория.
  Секрет копией не считается: записанный секрет нельзя прочитать обратно. Потеря
  ключа означает, что обновить уже установленные копии будет нечем, а переустановка
  сотрёт данные (`allowBackup=false`). Что и куда сохранять — [docs/CLOUD.md](docs/CLOUD.md).
- **APK релиза ~69 МБ**: модели ML Kit (сканер и OCR) вшиты в приложение. Лечится
  переходом на unbundled-модели через Google Play Services — ценой загрузки при первом
  запуске сканера. Пока не делалось: приложение ставится вручную и обновляется по Wi-Fi.
- **`ProductScreen.kt` — около тысячи строк**, вдвое с лишним больше следующего файла.
  Бизнес-логики в нём нет, detekt исключает Compose-экраны из `LongMethod` осознанно,
  но диалоги и секции просятся в отдельные файлы.
- **Совместный доступ остановлен на этапе 1** (обмен журналами через общую папку).
  Этап 2 — обмен по локальной сети — нужен, только если задержка облачной папки
  окажется неудобной на практике ([ADR-0004](docs/adr/0004-household-sharing.md)).

## Следующий шаг

Выпустить **1.12.0** из накопленного:

1. `versionCode = 14`, `versionName = "1.12.0"` в `app/build.gradle.kts` —
   versionCode обязан вырасти, иначе Android не примет обновление, а versionName
   обязан совпасть с тегом, иначе приложение будет вечно предлагать уже
   установленное обновление (`UpdateChecker` сравнивает `tag_name` с `VERSION_NAME`).
2. Перенести `## [Unreleased]` в `## [1.12.0] — дата` в `CHANGELOG.md`.
3. Отправить в `main`, дождаться зелёного CI.
4. **Actions → Release → Run workflow**, версия `1.12.0`. Workflow сам сверит
   отпечаток сертификата с `EXPECTED_CERT_SHA256` и откажется публиковать APK,
   подписанный не тем ключом.
