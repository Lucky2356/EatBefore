# Состояние проекта

Обновлено: 2026-07-14. Milestones **Foundation**, **Сканер**, **OCR срока** — завершены.

## Milestone «OCR срока годности» (что реализовано и проверено)

- `ExpiryDateParser` (чистый, 11 unit-тестов): форматы dd.MM.yyyy / dd.MM.yy / MM.yyyy /
  ISO / «dd MON yyyy» (EN+RU месяцы); month-year → конец месяца; различие «годен до» и
  «дата изготовления» по близости метки; ранжирование по уверенности; отсев неправдоподобных дат.
- `MlKitExpiryDateOcrProvider`: ML Kit text recognition on-device, лимит размера изображения,
  устойчивость к ошибкам (пустой результат вместо падения).
- Экран OCR: CameraX ImageCapture, показ исходного текста и кандидатов, подтверждение
  пользователем, экран «Дата не распознана», снимок удаляется после обработки (приватность).
- Интеграция: кнопка «Распознать по фото» в форме добавления, дата возвращается в форму.
- Проверено на эмуляторе (API 35): съёмка → распознавание → корректный экран «не распознано»
  (виртуальная сцена без даты) → возврат в форму; временный файл снимка удалён.

## Milestone «Сканер» (что реализовано и проверено)

- CameraX preview + ML Kit barcode (on-device): EAN-13/8, UPC-A/E, QR, DataMatrix,
  Code-128; подсветка области, фонарик, антидубль (3 с), ручной ввод кода, устойчивая
  обработка отсутствия/отказа камеры (без падения).
- Реальный `ProductCatalogProvider` на Open Food Facts (OkHttp, таймауты 5/5/8 с,
  User-Agent, HTTPS); ответы валидируются как недоверенные; ошибка/не найдено не
  блокируют ручной ввод. Найденный товар кешируется локально (SCAN_CACHE).
- Поток: найден → «Добавить упаковку» / «Подробнее»; не найден/ошибка → добавить вручную
  (форма предзаполняется штрихкодом). Запрос разрешения камеры — в момент использования.
- Проверено на эмуляторе (API 35): ввод кода 3017620422003 → найден «Nutella» из каталога
  → добавлена упаковка (Холодильник, «Без срока») → на главной «Всего продуктов: 2».
- Тесты: `LookupProductByBarcodeUseCaseTest` (кеш-хит без сети, кеширование сетевого
  результата, ошибка/не найдено). Всего 32 unit/интеграционных теста, 0 падений.

## Что реализовано

- Тулчейн настроен (JDK 21 из Android Studio, Android SDK Platform 36, build-tools).
- Gradle-проект: Version Catalog, Compose, Hilt, Room, KSP, wrapper 8.11.1, AGP 8.10.1.
- Модель данных Room: products, inventory_batches, inventory_events, storage_locations,
  shopping_list_items; converters, индексы, seed мест хранения, экспорт схемы v1.
- Домен: модели, enum-ы, интерфейсы репозиториев и провайдеров, 11 use cases.
- Data: реализации 4 репозиториев, мапперы, атомарные мутации с записью истории,
  fake-провайдеры каталога и OCR.
- Дизайн-система: тема M3 (светлая/тёмная + dynamic color), статус-бейджи (иконка+текст),
  empty/error/loading, quick-action кнопки, форматтеры.
- Экраны: онбординг (3 стр.), главная, запасы (поиск/фильтр/сортировка), ручное
  добавление, карточка продукта (быстрые действия + история + undo), история
  (фильтры, восстановление, отмена последнего). Нижняя навигация + NavHost.
- Заглушки-«coming soon»: сканер (ведёт к ручному добавлению), покупки, ещё.

## Известные проблемы / ограничения

- Runtime-проверка на устройстве не выполнена: на машине нет AVD/устройства. Стек
  проверен интеграционными тестами на JVM (Robolectric); сборка APK не блокируется.
- `product` карточка показывает историю по продукту; постраничная загрузка больших
  историй ещё не добавлена (сейчас списки небольшие).
- Экспорт/импорт и реальные внешние сервисы отсутствуют (заглушки/интерфейсы).
