## Что вошло в 1.14.0

Хвосты ROADMAP, которые действительно не были сделаны.

- **Категория задаётся при добавлении**, а не только потом в диалоге правки. Над полем —
  уже заведённые категории: без них одно домохозяйство обзаводится «молочка», «Молочное»
  и «молоко» как тремя разными вещами. Побочно точнее стала подсказка «сколько хранится
  после вскрытия»: она считается по названию **и** категории.
- **Фотография товара в результате сканирования.** Диалог всплывает сразу после наведения
  камеры, и вопрос там один: это моё или каталог подставил не то. Название на него
  отвечает плохо, картинка — мгновенно.
- **Срок годности распознаётся по фотографии из галереи.** Раньше путь был один — снять
  кадр здесь и сейчас; при занятой или неразрешённой камере оставался только ручной ввод.
  Кнопка есть и на экране «нужен доступ к камере», где она нужнее всего.
- **Напоминания можно выключить для одного продукта** (схема v3 → v4). Это свойство
  карточки, а не телефона: выключенное напоминание уезжает на второй телефон и попадает
  в резервную копию. Обновление ничего не заглушает само.
- Попутно: удаление снимка после распознавания ограничено кэшем приложения — раньше оно
  шло по пути из URI и, попадись файл пользователя, удалило бы его.

## Что вошло в 1.13.0

Релиз про то, чего пользователь не видел, — и про вес.

- **Обмен перестал рапортовать об успехе, ничего не отправив.** `SyncManager` публикует
  журнал через SAF, а SAF отвечает «файла не будет» не исключением, а `null`; оба таких
  случая проваливались через голый `return`, после чего `sync()` всё равно переставлял
  отметку времени и возвращал `Success`. Сосед продолжал читать прошлый журнал, и оба
  телефона считали, что синхронизировались. Теперь это `Failed`, с тестом на регрессию.
- **Импорт не начинается без страховочной копии**, а автокопии и обмен включаются только
  при действительно выданном постоянном доступе к папке.
- **Камера объясняет свой отказ.** Раньше сканер показывал чёрный прямоугольник с
  подсказкой «наведите камеру», а на экране OCR кнопка затвора не делала вообще ничего.
- **Экран истории заговорил**: неудавшееся восстановление и «отменять нечего» больше не
  проходят молча.
- **APK 69 → ~35 МБ**: из release-сборки убраны ABI `x86` и `x86_64`, нужные только
  эмулятору. Обновление, которое приложение качает по Wi-Fi само, стало вдвое короче.

## Известные ограничения

- **Ключ подписи существует в двух местах** — у владельца и в секретах репозитория.
  Секрет копией не считается: записанный секрет нельзя прочитать обратно. Потеря
  ключа означает, что обновить уже установленные копии будет нечем, а переустановка
  сотрёт данные (`allowBackup=false`). Что и куда сохранять — [docs/CLOUD.md](docs/CLOUD.md).
- **APK релиза ~35 МБ**: нативные библиотеки ML Kit вшиты в приложение и весят около
  15 МБ на каждую из двух оставшихся ABI. Уменьшить дальше можно только переходом на
  unbundled-модели через Google Play Services — ценой загрузки при первом запуске сканера
  и зависимости от Play-сервисов. Для local-first приложения это плохой обмен.
- **`ProductScreen.kt` — около тысячи строк**, вдвое с лишним больше следующего файла.
  Бизнес-логики в нём нет, detekt исключает Compose-экраны из `LongMethod` осознанно,
  но диалоги и секции просятся в отдельные файлы.
- **Совместный доступ остановлен на этапе 1** (обмен журналами через общую папку).
  Этап 2 — обмен по локальной сети — нужен, только если задержка облачной папки
  окажется неудобной на практике ([ADR-0004](docs/adr/0004-household-sharing.md)).

### Порядок выпуска следующей версии

1. `versionCode` и `versionName` в `app/build.gradle.kts`. versionCode обязан
   вырасти, иначе Android не примет обновление; versionName обязан совпасть с тегом,
   иначе приложение будет вечно предлагать уже установленное (`UpdateChecker`
   сравнивает `tag_name` с `VERSION_NAME`).
2. Перенести накопившееся из `## [Unreleased]` в `## [X.Y.Z] — дата` в
   `CHANGELOG.md`: описание релиза собирается из этого раздела скриптом
   `.github/scripts/release_notes.py`, и без раздела workflow остановится.
3. Отправить в `main`, дождаться зелёного CI.
4. **Actions → Release → Run workflow**, ввести версию. Workflow сверит отпечаток
   сертификата с `EXPECTED_CERT_SHA256` и откажется публиковать APK, подписанный не
   тем ключом. Галочка **dry run** проходит тот же путь, но вместо публикации кладёт
   подписанный APK в артефакты — так проверяются секреты, когда публиковать нечего.
