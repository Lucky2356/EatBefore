# Каталог товаров: что подключено и почему

Жалоба «многие продукты не находятся» — реальная, но её причина не в коде.
Ниже — что было проверено и что с этим сделано.

## Российских бесплатных API не существует

Проверено запросами (июль 2026):

| Источник | Результат |
|---|---|
| **«Честный знак»** (`mobile.api.crpt.ru`) | HTTP **451** — закрыт для внешних клиентов |
| **Национальный каталог** (`апи.национальный-каталог.рф`) | HTTP **501** без ключа; ключ платный, по договору |
| **opengtindb.org** | `error=5` даже на заведомо существующем товаре — база мертва |
| **barcode-list.ru** | HTTP **403** — блокирует программные запросы |
| **upcitemdb** (trial) | Отвечает, но `total: 0` даже на известных EAN — покрытия нет |
| **Wikidata** (GTIN P3962) | Пустой результат — товары туда почти не заносят |

Вывод: **российского добавлять нечего**. Поэтому выигрыш пришлось искать в другом
месте — сначала в `product_type=all` (ниже), а с 1.16.0 ещё и во втором, зарубежном
каталоге Go-UPC с ключом владельца (см. раздел о нём и
[ADR-0008](adr/0008-second-catalog-go-upc.md)).

## Что реально дало прирост: `product_type=all`

Раньше запрос шёл только в базу **еды**. У Open Food Facts есть ещё три базы —
косметика, бытовые товары и корма для животных, — и параметр `product_type=all`
ищет по всем сразу: сервер отвечает редиректом (302) на ту базу, где товар
лежит, а OkHttp следует за ним автоматически.

Проверено на реальных кодах:

| Штрихкод | Только еда | `product_type=all` |
|---|---|---|
| `3574661527925` | не найден | **Hand Cream** (beauty) |
| `8006540818824` | не найден | **Capitain Extra XL** (beauty) |
| `4620017700531` | Tea nic лимон | Tea nic лимон |

То есть шампунь, стиральный порошок или корм для кота раньше **не могли**
найтись в принципе. Теперь могут. У непищевых товаров часто пустое поле
`categories`, поэтому категория выводится из того, какая база ответила.

## Цепочка провайдеров

`ChainedCatalogProvider` опрашивает источники по очереди и возвращает первое
попадание: сначала Open Food Facts, потом Go-UPC (если введён ключ). Важна логика
ошибок:

- источник ответил «не знаю такой код» → пробуем следующий;
- источник **упал** (таймаут, 503) → запоминаем ошибку, но продолжаем: товар
  может быть в следующем;
- «не найдено» возвращается, только если **все** источники ответили штатно.

Разница принципиальная: на «не найдено» интерфейс сразу предлагает ручной ввод,
а на ошибку — повтор. Спутать их — значит соврать пользователю, что товара не
существует, когда мы просто не дозвонились. Это покрыто тестами
(`ChainedCatalogProviderTest`).

## Второй каталог: Go-UPC (с 1.16.0)

Проверка на 44 популярных российских штрихкодах (сентябрь 2026): Open Food Facts
нашёл 27; Go-UPC на первых 30 — 25 против 19 у Open Food Facts, вместе — 26 из 30.
Названия у Go-UPC собраны с магазинов всего мира и бывают на другом языке или с
«Купить в Алматы» на конце, поэтому:

- находка из Go-UPC **не становится карточкой сама** — сканер показывает «Похоже,
  это…» и открывает форму с подставленным названием, подписанным «Название из Go-UPC —
  проверьте и поправьте»;
- в режиме «из магазина» такой код откладывается вместе с неизвестными, форма потом
  откроется уже заполненной;
- повторный скан того же кода запрос не тратит.

**Ключ — свой.** Бесплатный тариф — 150 запросов в месяц, заявка на
go-upc.com/plans/api/trial. Ключ вводится в «Настройки → Каталог товаров → Ключ
Go-UPC», хранится зашифрованным (`GoUpcKeyStore`), в бэкап не попадает, на втором
телефоне вводится отдельно. Запрос уходит, только когда товара нет ни в памяти
телефона, ни в Open Food Facts, и в нём только штрихкод.

Если Go-UPC отказал в ключе или месяц исчерпан, скан ведёт в ручную форму как «не
найдено», а в настройках появляется причина. «Проверить ключ» тратит один запрос:
бесплатного способа нет, формат кода сервис проверяет раньше ключа.

```bash
curl -s -H "Authorization: Bearer <ключ>" https://go-upc.com/api/v1/code/4607053473537
```

## Отправка товаров обратно в базу

Единственный способ реально закрыть пробел по России — пополнять общую базу.
Пользователь один раз вводит название, отправляет, и дальше код распознаётся у
всех, включая его самого на другом телефоне.

**Требуется личный аккаунт** на openfoodfacts.org: API отклоняет анонимные
записи. Общий «аккаунт приложения» зашивать в APK нельзя — он извлекается из
файла, и все правки шли бы от одного имени, что каталог считает злоупотреблением.

Как устроено:

- аккаунт привязывается в «Настройки → Каталог товаров», по умолчанию не привязан;
- пароль шифруется через Android Keystore (`SecretCipher`, AES/GCM) и **не
  попадает в бэкап** — это проверяется тестом;
- отправка предлагается **каждый раз отдельно**, после ручного ввода товара со
  штрихкодом, и никогда не происходит молча;
- уходят только штрихкод, название, бренд и объём. Запасы, сроки, места
  хранения и история не отправляются никогда.

## Лимиты

Open Food Facts: **15 запросов в минуту на IP** для чтения товара, право
блокировки за неопознанные обращения. `User-Agent` обязан быть в формате
`AppName/Version (contact)` — задан в `OpenFoodFactsCatalogProvider`. На 429/503
провайдер делает три попытки с нарастающей паузой, потом честно отдаёт ошибку.

## Как проверить код руками

```bash
curl -sL -A "EatBefore/1.4.0 (test)" "https://world.openfoodfacts.org/api/v2/product/4620017700531.json?product_type=all&fields=product_name,product_type"
```

Если тут пусто — товара нет в базе, и никакой код приложения этого не изменит.
Это ровно тот случай, когда нужна отправка (см. выше).
