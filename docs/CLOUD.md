# Проект целиком на GitHub

Разработка, сборка, тесты и публикация релиза живут на стороне GitHub. На своём
компьютере не нужно ничего, кроме браузера: ни JDK, ни Android SDK, ни Android
Studio, ни эмулятора.

Репозиторий публичный, поэтому минуты Actions не расходуются и не ограничены —
включая двадцатиминутный прогон инструментальных тестов на эмуляторе.

## Что нужно сохранить руками, прежде чем стирать систему

В git попадает только код. Ниже — то, чего в репозитории нет и не должно быть.

1. **`eatbefore-release.jks` — ключ подписи. Восстановить невозможно.** Android
   принимает обновление, только если оно подписано тем же ключом; без файла
   обновить уже установленные копии будет нечем, а переустановка сотрёт данные
   (`allowBackup=false`). Скопируйте файл и пароль к нему в менеджер паролей и на
   внешний носитель.
   **Секрет GitHub копией не считается: записанный секрет нельзя прочитать обратно.**
2. **`local.properties`** — пути и пароли подписи. Восстанавливается за минуту, но
   пароли в нём те же самые, что в пункте 1.
3. **Экспорт данных приложения с телефонов** — «Ещё → Настройки → Данные → Экспорт
   копии». К компьютеру отношения не имеет, но это единственная копия того, что
   действительно нельзя пересоздать.
4. **`~/.claude`** — настройки и память Claude Code, если хотите сохранить контекст
   прошлых сессий.

Проверить, что в самом репозитории ничего не забыто:

```bash
git status --short && git log --oneline origin/main..HEAD
```

Пусто и там и там — всё отправлено.

## Сборка и проверки

Workflow **CI** (`.github/workflows/ci.yml`) идёт на каждый push и pull request:
формат, detekt, юнит-тесты, lint и сборка debug-APK. APK кладётся в артефакты
запуска, так что его можно скачать со страницы Actions.

Инструментальные тесты на эмуляторе — только на push в `main`: они занимают около
двадцати минут, и среди них единственная автоматическая защита от потери данных при
обновлении (тест миграции Room).

### Проверить формат, не дожидаясь CI

Круг CI занимает пять минут, и обиднее всего потратить его на порядок импортов. ktlint —
самостоятельный бинарник, которому не нужны ни Gradle, ни Android SDK, поэтому его можно
держать под рукой где угодно, включая среду без SDK:

```bash
curl -sSLo ktlint https://github.com/pinterest/ktlint/releases/download/1.5.0/ktlint
chmod +x ktlint
./ktlint --relative "app/src/**/*.kt"
```

Версия должна совпадать с `ktlint` в `gradle/libs.versions.toml`. Учтите: запущенный так
ktlint берёт стиль `ktlint_official` по умолчанию, а проект настраивает spotless иначе
(`build.gradle.kts`, `ktlintRules`), поэтому он ругается и на давно лежащий в репозитории
код. Смотреть надо на правила, которых касаются именно ваши строки, — в первую очередь
`standard:import-ordering`: порядок лексикографический, и прописные буквы в нём идут
раньше строчных (`StateFlow` перед `asStateFlow`, `com.eatbefore.R` перед
`com.eatbefore.core`).

## Релиз

Workflow **Release** (`.github/workflows/release.yml`) собирает подписанный APK и
публикует его сам. Порядок:

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`.
2. Перенести накопившееся из `## [Unreleased]` в `CHANGELOG.md` в раздел
   `## [X.Y.Z] — дата`.
3. Отправить это в `main` и дождаться зелёного CI.
4. **Actions → Release → Run workflow**, ввести версию (и, если хочется, заголовок).

Галочка **dry run** проходит всё то же самое, но вместо публикации кладёт готовый
подписанный APK в артефакты запуска. Так проверяются секреты и подпись, когда
публиковать ещё нечего — например, сразу после настройки ключа.

Workflow ничего не коммитит сам: тег должен указывать ровно на то, что собрано.
Прежде чем тратить время на сборку, он проверяет, что версия совпадает с
`versionName`, что такого релиза ещё нет и что раздел в `CHANGELOG.md` существует.

Описание релиза делается из этого раздела скриптом
[`.github/scripts/release_notes.py`](../.github/scripts/release_notes.py): диалог
обновления в приложении показывает текст как есть, поэтому Markdown из него убирается,
а перенесённые строки склеиваются обратно в абзацы.

Собранный APK проверяется по отпечатку сертификата. Это не формальность: без ключа
сборка молча подписывается отладочным (см. `app/build.gradle.kts`), а такой APK не
встанет поверх установленного приложения — и выяснилось бы это уже на телефоне.

### Ключ подписи в секретах

Один раз, на машине, где ключ ещё есть:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-release-secrets.ps1
```

Скрипт читает `local.properties` и создаёт четыре секрета репозитория:
`EATBEFORE_KEYSTORE_BASE64`, `EATBEFORE_STORE_PASSWORD`, `EATBEFORE_KEY_ALIAS`,
`EATBEFORE_KEY_PASSWORD`. Значения он не печатает.

Если машины с ключом уже нет, то же самое делается вручную из любой системы:

```bash
base64 -w0 eatbefore-release.jks | gh secret set EATBEFORE_KEYSTORE_BASE64
gh secret set EATBEFORE_STORE_PASSWORD
gh secret set EATBEFORE_KEY_ALIAS
gh secret set EATBEFORE_KEY_PASSWORD
```

## Разработка в браузере

В репозитории есть описание облачной среды
([`.devcontainer/`](../.devcontainer/devcontainer.json)): **Code → Codespaces →
Create codespace**. При создании ставятся JDK 17 и Android SDK, дальше работают
обычные команды:

```bash
./gradlew :app:assembleDebug
./gradlew spotlessCheck detekt :app:testDebugUnitTest :app:lintDebug
```

Первое создание занимает несколько минут: SDK и кэш Gradle вместе — около 10 ГБ.

Чего в Codespaces нет и не будет: **эмулятора**. Виртуализации внутри контейнера
нет, поэтому `connectedDebugAndroidTest` там не запустится — эти тесты идут в
Actions, где KVM включается отдельным шагом. Проверять руками по-прежнему проще
всего на своём телефоне: скачать debug-APK из артефактов CI.

## Что осталось привязано к устройству

**Baseline Profile.** Профили лежат в репозитории и продолжают работать, но
пересобрать их (`:app:generateBaselineProfile`) можно только на устройстве с root —
см. [BASELINE_PROFILE.md](BASELINE_PROFILE.md). В облаке этого сейчас нет, так что
профили будут понемногу устаревать по мере изменения экранов. На корректность это не
влияет, только на скорость первого запуска.

**Скриншоты в README** снимаются с работающего приложения — их обновление тоже
требует устройства или эмулятора.

Бесплатная квота Codespaces у личного аккаунта ограничена (часы ядра в месяц), и
остановленная среда её не тратит — но диск занимает. Ненужные удаляйте на странице
[github.com/codespaces](https://github.com/codespaces).
