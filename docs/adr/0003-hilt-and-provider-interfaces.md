# ADR 0003: Hilt и провайдеры за интерфейсами

- Статус: принято
- Дата: 2026-07-14

## Контекст

Нужен предсказуемый DI с минимумом бойлерплейта и точки расширения для внешнего каталога,
OCR и (в будущем) облачной синхронизации, не встраивая их в локальную бизнес-логику.

## Решение

- DI — **Hilt** (стандарт экосистемы, генерация компонентов, интеграция с ViewModel/Work).
- Внешние возможности спрятаны за доменными интерфейсами: `ProductCatalogProvider`,
  `ExpiryDateOcrProvider`; репозитории — тоже интерфейсы в `domain`, реализации в `data`.
- На этапе Foundation интерфейсы связаны с рабочими заглушками
  (`FakeProductCatalogProvider`, `NoopExpiryDateOcrProvider`).
- Сканер планируется на **ML Kit** (on-device, офлайн, без сети/трекинга) — см. ROADMAP.

## Последствия

- (+) Реализации сервисов подменяемы без изменения бизнес-логики и UI; удобно тестировать.
- (+) Домен не зависит от Android/сетевых DTO.
- (−) ML Kit — зависимость Google (полностью on-device); для максимальной «чистоты»
  возможна альтернатива ZXing (зафиксировано как опция).
