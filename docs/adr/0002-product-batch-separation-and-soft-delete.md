# ADR 0002: Разделение продукт/партия и soft-delete

- Статус: принято
- Дата: 2026-07-14

## Контекст

Один товар может присутствовать дома в нескольких упаковках с разными сроками и в разных
местах. Использованные/выброшенные позиции нужны для истории, аналитики и восстановления.

## Решение

- Разделяем `Product` (карточка — что это) и `InventoryBatch` (конкретная партия запаса).
- Партии не удаляются физически при обычных операциях: используется soft-delete
  (`deletedAt`) + терминальные статусы (`CONSUMED`/`DISCARDED`/`ARCHIVED`).
- История (`InventoryEvent`) — append-only; исправления вносятся компенсирующими
  событиями (`RESTORED`, обратный `MOVED`), а не изменением прошлых записей.
- Каждая мутация запаса и её событие пишутся атомарно в одной транзакции Room.

## Последствия

- (+) Несколько партий одного товара; корректная история и восстановление; надёжный
  аудит-лог, не расходящийся с данными.
- (+) База для аналитики отходов/потребления.
- (−) Запросы «present» должны фильтровать по статусу и `deletedAt` — инкапсулировано в DAO.
- (−) Данные накапливаются (не удаляются); при необходимости — архивация/очистка позже.
