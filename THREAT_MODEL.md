# Threat Model

Скелет модели угроз. Наполняется по мере добавления сети, камеры, OCR и
экспорта/импорта. Уже учтённое на этапе Foundation отмечено ✅.

## Активы

- Локальные данные пользователя (продукты, история, настройки).
- Целостность базы данных и аудит-лога.
- Доступность приложения (устойчивость к сбоям).

## Границы доверия

- Ввод пользователя (ручное добавление).
- Данные внешнего каталога по штрихкоду (будущее) — **недоверенные**.
- Содержимое QR/штрихкодов — **недоверенные данные**.
- Импортируемые файлы резервных копий (будущее) — **недоверенные**.
- Изображения для OCR (будущее) — потенциально повреждённые/вредоносные.

## Угрозы и меры

| Угроза | Мера | Статус |
|--------|------|--------|
| Слишком длинные значения / переполнение | `InputValidator` (лимиты длины, clamp количества) | ✅ |
| SQL-инъекции | Параметризованные запросы Room, отсутствие конкатенации SQL | ✅ |
| Выполнение содержимого QR | Код трактуется как данные; ничего не исполняется/не открывается | ✅ (политика) |
| Случайное удаление | Soft-delete + подтверждение опасных операций + undo | ✅ |
| Рассинхрон истории и данных | Атомарные транзакции (мутация+событие) | ✅ |
| Гонки при одновременном изменении | Транзакции Room, единый источник истины | ✅ |
| Некорректные даты | Валидация в use cases, `LocalDate` | ✅ |
| Разрушающая миграция БД | Только явные `Migration`, без destructive fallback | ✅ |
| Утечка секретов | Секреты не в репозитории; логирование без чувствительных данных | ✅ |
| Системный бэкап данных | `allowBackup=false`, правила извлечения исключают всё | ✅ |
| Подмена ответов внешнего API | HTTPS, валидация/санитация ответа, данные редактируемы, таймауты, не блокируют ручной ввод | ✅ |
| Вредоносные данные в коде (переполнение/управляющие символы) | `InputValidator` для распознанного значения; штрихкод только как данные | ✅ |
| Path traversal при импорте/экспорте | Проверка путей, SAF, версия схемы, проверка целостности | ⏳ (с бэкапом) |
| Вредоносные изображения / OOM | Ограничение размера, безопасная декодировка, thumbnail | ⏳ (с OCR) |
| Небезопасные deep links | Явная валидация, отсутствие автозаполнения из недоверенных источников | ⏳ |
| Повторное/двойное добавление | Защита от двойного нажатия, дедупликация продукта | ✅ (частично) |

## Обработка ошибок

Пользователю показываются понятные сообщения без stack trace; технические детали не
утекают. Повтор операций — там, где это безопасно.
